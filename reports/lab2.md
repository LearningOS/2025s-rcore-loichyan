## 问答题

### SV39 页表项的组成

本质上，页表项由数据段和标志段组成，具体而言：

```text
[ Reserved ][ Physical Page Number ] [ RSW ] [ DAGUXWRV ]
  10b         44b                      2b      8b
  │           │                        │       └>(d) 内存页权限以及读写状态
  │           │                        └>(c) 操作系统保留
  │           └>(b) 物理内存页编号
  └>(a) RISC-V 保留
```

其中，

- `(b)` 和 `(c)` 由操作系统管理．标志段 `(c)` 常用于辅助操作系统实现特定的页面替换或加载算法等．
- `(d)` 由操作系统和处理器共同管理．操作系统主要用来控制内存的访问权限；而处理器主要用来设置该页面的读写状态，以便操作系统进一步决策．

### 缺页

1. `InstructionPageFault`, `LoadPageFault` 和 `StorePageFault` 均可由缺页导致．
2. 发生缺页时，最重要的寄存器是 `stval`，它记录了引发缺页的地址．此外，其它通用寄存器也可能记录了被访问的页面，不过这取决于发生异常的上下文，除调试外实际作用不大．
3. 操作系统无法预知用户进程所需要的数据，通过 Lazy 策略实现按需加载，减少不必要的 I/O 从而提高整体的性能．
4. 对于 10GB 的连续页面，页表占用 20MB 左右的内存．
5. 简单的 Lazy 策略：预先分配好页表，但所有的页表项都置为 Invalid（即不设置 V 标记），同时记录页表中每项对应的文件数据段．当捕捉到用户态缺页异常时，如果是懒加载页面，完全对应数据段的载入并返回用户态重新访存．
6. 页面失效时，页表项 V 标记为 `0`，RSW 标记段依操作系统实现的页面管理算法可能有特殊含义．

### “单页表”与“双页表”

1. 单页表情况下，不使用页表隔离的情况下，每个用户进程有自己的页表，该页表同时包括用户空间和内核空间[^1]，用户空间位于整个内存空间的低位，而内核被映射到高位．因此，仅需要切换进程时加载对应的页表即可．而在开启页表隔离时，以 Linux 的 PTI 策略为例[^2]，每个用户进程有两份页表，一份仅包括用户空间和少量内核代码（比如跳板页），另一份还包含了完整的内核空间（出于安全考虑，用户空间的执行权限可能被关闭）．进程初始化时，两份页表被放在连续的两个物理页框，这样，当用户态发生陷入时，只需要少量按位操作就能实现页表的切换．
2. 如上所述，单页表情况下，不开启隔离时，需要关闭内核空间的用户访问权限（即不设置 U 标记）；开启隔离时，内核空间对用户完全不可见，因此可以防治 Meltdown 攻击．
3. 单页表的优势：i) 在内核中访问用户内存时不需要进行地址转换；ii) 处理陷入时不需要清除用户空间的高速缓存；iii) 在内核中读写用户空间时亦不需要考虑跨页访问带来的问题．劣势：i) 需要使用页表隔离技术来增强安全性；ii) 需要硬件支持来实现缓存的细粒度控制；iii) 内核在物理内存中的位置不同于其在虚拟内存中的位置，因此启动时需要使用部分汇编技巧来初始化内核空间（也可以完全编译成位置无关的代码，即 PIC）．
4. 双页表情况下，内核程序和用户程序被映射到相同的内存空间，可能会发生重叠，因此处理陷入时必须要清空缓存并切换至内核页表．如上所述，考虑性能时不开启页表隔离，仅在进程更替时切换页表；考虑安全时开启页表隔离，每次处理陷入时都需要换表．
